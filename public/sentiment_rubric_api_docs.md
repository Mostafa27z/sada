# توثيق واجهة برمجة التطبيقات: معايير تحليل المشاعر والمواقف المخصصة
# API Documentation: Custom Sentiment & Stance Rubric Engine

نظام صدى (Sada Intelligence) يتيح للعملاء تخصيص زوايا ومعايير تحليل المشاعر (Custom Sentiment & Stance Rubric) للمقالات والتعليقات والمنشورات بدلاً من الاعتماد على التحليل اللغوي السطحي فقط.

---

## 1. المفهوم المعماري (Stance & Contextual Rubric)
في نماذج تحليل المشاعر السطحية:
- كلمات مثل *"جريمة بشعة / مجرم قذر / إعدام"* تُصنف لغوياً كسلبية (Negative)، مع أن إدانة الجريمة وشجبها في تريند جريمة هو **موقف إيجابي (+)** يدعم العدالة والمجتمع، بينما تبرير الجريمة أو الدفاع عنها هو **الموقف السلبي (-)**.
- في أخبار النزاعات أو الحروب، تحديد الطرف الحليف والطرف الخصم يوجه التحليل: نقد الطرف الخصم أو الاحتفاء بانتصار الطرف الحليف يعتبر **إيجابياً (+)**، والعكس صحيح.

يدعم النظام مستويين للتطبيق:
1. **المستوى العام للمنشأة (Global Company Settings)**: معيار دائم للمنشأة يُطبق تلقائياً على كل عمليات الرصد والتحليل اليومية.
2. **المستوى المخصص لكل عملية تحليل (Per-Analysis Specific Preferences)**: معيار خاص بحملة أو رصد تريند معين يتجاوز المعيار العام.

## 2. هيكل بيانات المعيار (Rubric Schema)

```json
{
  "topic_context": "سياق القضية أو الموضوع (مثال: تريند قضية اختلاس شركة كذا / النزاع الإقليمي)",
  "stance_description": "الموقف العام والتوجه الاستراتيجي للمنشأة",
  "preferred_side": "الطرف أو القضية التي تتبناها المنشأة (الحليف / العدالة / حماية المجتمع)",
  "opposed_side": "الطرف أو الظاهرة المعارضة (الخصم / المعتدي / الجريمة / المحتالين)",
  "positive_rules": "ما يُعتبر إيجابياً (+) بالنسبة للعميل (مثال: شجب الجريمة والمجرم، الإشادة بنزاهة القضاء، انتصارات الطرف الحليف)",
  "negative_rules": "ما يُعتبر سلبياً (-) بالنسبة للعميل (مثال: تبرير الجريمة، الدفاع عن الجناة، مهاجمة الحليف، الترويج للخصم)",
  "neutral_rules": "ما يُعتبر محايداً (نقل الإحصائيات والأرقام والبيانات الرسمية المجردة دون اتخاذ موقف)"
}
```

## 3. نقاط النهاية الخاصة بإعدادات المنشأة العامة (Global Settings)

### 3.1 جلب المعيار العام للمنشأة
* **المسار:** `GET /api/v1/tenant/sentiment-rubric`
* **المصادقة:** `Bearer Token` (مطلوبة)
* **Headers:** `Accept: application/json`

**نموذج الاستجابة (Response):**
```json
{
  "success": true,
  "message": "Success",
  "data": {
    "tenant_id": 21,
    "tenant_name": "stylac",
    "sentiment_rubric": {
      "topic_context": "السياسة التحريرية لمكافحة الاحتيال والجرائم المالية",
      "stance_description": "المنشأة تدعم النزاهة المالية وحماية المستهلك والشفافية",
      "preferred_side": "النزاهة والجهات الرقابية",
      "opposed_side": "الاحتيال والمخالفين",
      "positive_rules": "استنكار الجرائم والاحتيال، الإشادة بالقضاء والجهات الرقابية، حماية المستهلكين",
      "negative_rules": "تبرير الاحتيال، التشكيك في نزاهة الأنظمة، التعاطف مع المخالفين",
      "neutral_rules": "نقل الأخبار والإحصائيات واللوائح التنظيمية الرسمية"
    }
  }
}
```

---

### 3.2 تحديث المعيار العام للمنشأة
* **المسار:** `PUT /api/v1/tenant/sentiment-rubric`
* **المصادقة:** `Bearer Token` (مطلوبة)
* **Headers:** `Content-Type: application/json`, `Accept: application/json`

**نموذج جسم الطلب (Request Body):**
```json
{
  "sentiment_rubric": {
    "topic_context": "السياسة التحريرية لمكافحة الاحتيال والجرائم المالية",
    "stance_description": "المنشأة تدعم النزاهة المالية وحماية المستهلك والشفافية",
    "preferred_side": "النزاهة والجهات الرقابية",
    "opposed_side": "الاحتيال والمخالفين",
    "positive_rules": "استنكار الجرائم والاحتيال، الإشادة بالقضاء والجهات الرقابية",
    "negative_rules": "تبرير الاحتيال أو التعاطف مع الجناة",
    "neutral_rules": "نقل الأرقام والبيانات المجردة"
  }
}
```

## 4. تطبيق معيار مخصص في حملات ومجموعات الرصد (Collections)

عند إنشاء أو تحديث مجموعة رصد (`POST /api/v1/collections` أو `PUT /api/v1/collections/{id}`):

**نموذج الطلب:**
```json
{
  "name": "رصد تريند قضية الاختلاس الكبرى",
  "keywords": ["قضية الاختلاس", "شركة سين", "الاحتيال المالي"],
  "platforms": ["x", "facebook", "instagram"],
  "country": "SA",
  "comments_limit": 50,
  "sentiment_rubric": {
    "topic_context": "قضية اختلاس مالي كبرى ضد شركة وطنية",
    "stance_description": "الوقوف مع الشركة والعدالة واستنكار الجريمة",
    "preferred_side": "القضاء والنزاهة والشركة المتضررة",
    "opposed_side": "المختلس والمتورطين",
    "positive_rules": "ذم المجرم واستنكار الجريمة والمطالبة بالعقاب وتطهير المجتمع (يعتبر إيجابياً ومؤيداً للحق)",
    "negative_rules": "تبرير السرقة والدفاع عن المتهم وإلقاء اللوم على الشركة (يعتبر سلبياً)",
    "neutral_rules": "البيانات الصادرة من النيابة والمحاكم بدون تعليق"
  }
}
```

* يتم حفظ المعيار في عمود `sentiment_rubric` بالمجموعة.
* يتم تمريره تلقائياً لكل من وظائف الطوابير (`ScrapeKeywordsJob` و `ScrapePostCommentsJob`).
* في حال عدم إرسال `sentiment_rubric` خاص بالمجموعة، يعتمد النظام تلقائياً على المعيار العام للمنشأة إن وجد.

## 7. حقول الاستجابة الجديدة للواجهة الأمامية (Frontend Integration)

عند استدعاء أي من واجهات المقالات (`ArticleResource`) أو التعليقات (`CommentResource`) أو المجموعات (`CollectionResource`):
* `sentiment`: ("positive" | "negative" | "neutral")
* `sentiment_score`: رقم عشري يوضح درجة التأكيد (مثال: `0.95`).
* `sentiment_reason`: سطر توضيحي باللغة العربية يشرح سبب التصنيف استناداً لمعيار الـ Rubric (Explainability).
* `sentiment_rubric`: كائن المعيار الخاص بالمجموعة إذا تم تخصيصه.
* `effective_rubric`: المعيار الفعّال المطبق (الخاص بالمجموعة إن وُجد، أو المعيار العام للمنشأة).
